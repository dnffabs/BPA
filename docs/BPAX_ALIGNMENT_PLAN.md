# 对齐 BPA-X 功能，再验证增强效果

日期：2026-10-26。

对照版本：本项目 `c4dd5b9` 加已冻结的未提交修改；本机 BPA-X `0fb0a51`。本文同时依据当前代码和 [首轮实测](experiments/20261026_PILOT_RESULTS.md)，不把论文目标、本机实现和实验已经证明的能力混为一谈。

实施更新：共同函数清单/独立覆盖、AT 与根策略、受限尾调用语义已实现，49 项完整回归通过。接口与限制见 [CONTROL_FLOW_ALIGNMENT.md](CONTROL_FLOW_ALIGNMENT.md)。下文差异表描述首轮实验时的基线状态；已落实项以此更新及机器清单状态为准，历史大型成绩不用于替代新版验证。

## 1. 目前的定位

本项目已经实现一条能够运行的二进制间接调用分析流水线：angr/CFGFast → VEX facts → 函数内定义使用关系 → 栈/全局/堆抽象 → 跨函数值传播与调用图联合不动点 → 目标和不确定性输出。

**已验证的优势集中在块内位置和调用点参数精化；BPA-X 当前更强的方面是若干基础语义、控制流处理和大型实验完成率。** 整体功能尚未对齐，因此现在的结果不能支撑“在真实程序上全面优于 BPA-X”。

两者都使用 angr/VEX 和 Soufflé。使用 VEX、SSA 或 Datalog 本身不是本项目相对 BPA-X 的新增贡献。

### 已经能做的事情

- 在有函数符号的 Linux X86 / AMD64 ELF 上运行完整流水线。
- 处理受支持的标量拷贝、地址计算、内存读写、条件选择，以及普通直接/间接调用。
- 联合推导跨函数参数、返回值、内存中的指针和新调用目标。
- 在可恢复时保留栈、全局和堆的字节偏移；内部指针经过返回、存储、加载后继续保留位置。
- 对普通 X86 栈参数、AMD64 寄存器参数及第 7/8 个栈参数建立传递关系。
- 对已认证的 outgoing 栈写入使用调用点到达快照；输出 unknown、unsupported 和 uncertain 诊断。

上述能力受当前指令覆盖和调用约定限制。普通内存仍然流不敏感，过程间仍然上下文不敏感；栈参数快照不是全程序流敏感内存 SSA。

## 2. 哪些优势已经有证据

| 能力 | 当前证据 | 可以得出的结论 | 尚不能得出的结论 |
| --- | --- | --- | --- |
| 同堆块字段分离 | 共同 heap-only/fields 小样例；BPA-X 同块目标合并，offset 可区分字段 | 保留偏移能减少这些案例中的目标污染 | 所有栈/全局情况都优于 BPA-X；大型程序整体更准 |
| 内部指针跨函数传播 | interior pointer 经返回、存储、加载再调用，32/64 位已核验 | 当前关系能够表达块内非零位置并跨过程传递 | 任意指针算术或任意库复制都已覆盖 |
| 参数位置与槽复用 | 双参数、AMD64 第 7/8 参数、到达写入规则测试 | 已认证场景中位置映射与快照有精化作用 | 所有栈参数场景都优于 BPA-X，或获得完整上下文敏感性 |
| 显式精确/未知位置 | `exact/unknown` 标签、complete_value 认证和对应测试 | 有利于受控精化、保留回退与问题定位 | unknown 自动包含所有真实调用目标，或已经证明 soundness |
| 模块和实验接口 | 分离的 facts/schema、三种内存模式、统一实验记录 | 适合继续扩展和做机制消融 | 性能已经优于 BPA-X |

共同小样例包含 11 个 ELF、21 个调用点、23 条真边。BPA-X 为 TP/FP/FN=`23/13/0`，本项目 offset 为 `23/2/0`。该集合围绕偏移和参数机制设计，不是任意真实程序的代表性样本。

### 一个直观例子

```c
struct Pair *p = malloc(sizeof(*p));
p->first = alpha;
p->second = beta;
p->first();
```

当一次堆分配被视为块 H 时，块内容只记录 `{alpha,beta}` 会合并两个字段。本项目可记录：

```text
H + 0 → alpha
H + 8 → beta        // 64 位例子
读取 H + 0 → alpha
```

这是本项目当前值得保留的增强。BPA-X 的栈/全局分块有时也能把不同变量分开，所以不能把“无偏移”直接理解为“所有变量都混在一起”。

## 3. 架构差异

### 3.1 共同基础

```text
ELF → angr / CFGFast → VEX → facts → Soufflé → 间接调用目标
```

当前两套实现主要都在前端已经提取的指令/facts 上求解。BPA-X 在 Datalog 中补调用/返回边，不代表每发现一条边就重新运行一次 angr 反汇编。本项目也已有新调用目标与值传播之间的递归，不能说完全没有 CFG/调用图不动点。

### 3.2 分块与值域不同

```text
BPA-X：多栈块/多全局块 + 分配点堆块 → 主要跟踪块身份
本项目：函数帧块/section 块 + 分配点堆块 → 跟踪块身份、偏移标签、偏移与访问宽度
```

这涉及两个独立问题：**对象如何划分**，以及**对象内部位置如何表示**。当前 offset 的未知位置会退化到一个大帧/大 section，容易扩大污染范围。BPA-X 的更细分块在部分场景可以限制这种污染。

因此，`--memory-model block` 只是关闭本项目的偏移精化，**不是 BPA-X 的等价实现**。它没有自动获得 BPA-X 的分块、尾调用、SSA、函数入口和宽度规则。`offset` 与 `block` 的内部对比也不能单独证明优于 BPA-X。

建议的长期组合是“合理的多对象分块＋块内偏移”。采用细块时，必须同步处理内部指针、数组跨子块访问和父对象回退，不能只切块而丢掉跨字段的合法地址关系。

### 3.3 SSA 与跨函数流不同

本项目先在 `rules/ssa.dl` 建立函数内 reaching definitions / def_use，再通过 `rules/analysis.dl` 的 call_input、entry_reg、exit_reg、call_output 连接参数和返回。新 call_edge 会递归增加 flow；函数内 def_use 不随新调用边重建。

BPA-X 在最终递归求解中，caller-saved 寄存器的 reaching definitions 经过包含调用/返回的全局 edge；callee-saved 寄存器主要沿局部边及 inter_succ 传播。新增调用/返回边可以改变全局到达定义。

**这是需要验证的设计差异，不是单凭代码形态就能证明本项目错误。** 函数摘要或入口/出口连接也可以正确建模跨函数流。应通过嵌套间接调用、递归、多返回点、保存寄存器与尾调用案例检查是否与预期语义等价，再决定是否引入增量过程间 RD 或完善摘要。

### 3.4 函数发现和分析根不同

- BPA-X 前端从 CFGFast 的函数集合生成范围，再做函数边界合并；预处理保留 main、address-taken 函数及其直接调用闭包。address-taken 指函数地址作为普通值出现在指令或全局数据中。
- 本项目明确要求 `.symtab`，按函数符号与 size 选取函数、提取函数体；最终分析从 main 出发。
- BPA-X 当前代码有基于 CFGFast 的函数发现入口。本轮没有验证其完全 stripped 场景的入口恢复、函数范围质量和分析准确性，不能写成已经可靠支持所有 stripped binary。

对齐时先提供共同函数清单/相同分析根的实验配置，再评估自动恢复。将 AT 函数纳入分析范围可以缓解前序漏边导致的未分析问题，但不能把这些候选直接当成“已证明从 main 可达”。

## 4. 功能对齐矩阵

状态说明：**已有基础**表示已有实现但不保证等价；**缺失**表示代码未覆盖；**增强**表示本项目已有值得保留的机制；**共有缺口**表示不能仅以复制 BPA-X 解决。

| 项目 | 本机 BPA-X | 本项目当前状态 | 对齐动作 |
| --- | --- | --- | --- |
| X86 / AMD64 | 两种架构的寄存器/ABI规则 | 已有基础，两种位宽已跑小样例 | 固定 X86 cdecl / AMD64 SysV 测试；暂不扩展 ARM/C++ |
| 函数清单与范围 | CFGFast 函数集合＋范围合并 | 符号/size＋CFGFast 函数体，拒绝无 symtab | 支持共同函数输入；检查函数别名、cold fragment、跳转跨范围；自动恢复单列验证 |
| AT 候选与分析根 | 显式 AT 检测，main＋AT 闭包 | 地址值可识别，main-rooted；没有等价的 AT 分析根配置 | 新增候选和根策略，区分 retained/reachable/unknown |
| 普通调用/返回 | 调用、返回边参与递归 edge/RD | 已有参数/返回 flow 与调用图递归；interproc_edge 主要是输出 | 核验返回定义、嵌套调用、新目标和递归；补足语义差异 |
| 直接/间接尾调用 | TC_Call、TC_Return、继承返回续点 | 仅报告 tail call / indirect jump，未加入等价传播 | **缺失：补尾调用目标、参数与继承返回关系** |
| 过程间 SSA / RD | caller-saved 全局、callee-saved 局部 | 函数内 RD＋入口/出口 flow | 独立差分验证；需要时增加动态过程间 RD/摘要更新 |
| 栈/全局分块 | 代码推断多块，normal/coarser/symtbl/dwarf 辅助模式 | 每帧/section 粗块 | 增加可选择的代码分块策略；DWARF 不作为主分析输入 |
| 堆抽象 | malloc/calloc/realloc 直接分配点 | 同类分配点＋偏移，X86 size 暂未知 | 保留偏移；补函数包装与间接分配器属于扩展，不假设 BPA-X 已全覆盖 |
| 标量指针语义 | 指针宽度读写、Add/Sub、ITE、32Uto64/64to32 等 | ITE/算术已有基础，动态 cast 规则和宽度策略不同 | 按运算、源宽度、目的宽度、寄存器子区间列清单；截断保留需有有效依据 |
| 只读全局块 | gblk_ro_key 阻止写入 rodata 块 | global_region 无权限属性，没有同等写入保护 | 保留 section/segment 权限和重定位阶段信息，防止伪别名污染只读内容 |
| 栈参数 | 调用点 SP、参数块、重叠区间映射 | 逐槽坐标映射＋已认证写入快照，尾调用未覆盖 | 对齐普通/尾调用坐标、未知 SP 回退，再独立比较快照收益 |
| 库函数副作用 | 有分配返回等专门规则，非完整库模型 | 有部分复制/分配摘要；当前复制摘要 ABI 参数绑定主要为 AMD64 | 按实际支持列表核对；不能假设任一方覆盖所有库回调/副作用 |
| 部分寄存器与 SIMD | 有宽度筛选；SIMD 复现中漏 alpha | 存在 partial write unknown；SIMD 复现仅输出错误 beta | **共有缺口：向量 lane / 字节片段传播是超越基线的明确方向** |
| 内存更新顺序 | 普通块内容主要按集合传播 | 普通内存弱更新；栈参局部快照 | 保留快照；全面流敏感/强更新作为后续增强 |
| unknown 与覆盖 | 没有本项目同形式的统一诊断 | 有诊断，但只看已判可达调用会掩盖漏路径 | 固定独立调用点全集；分列前端缺失、未纳入分析、无目标和部分已知目标 |
| 可扩展性 | 本轮完成 4/8 个大配置 | 各内存模式完成 1/8；32位 xz 600s 仍超时 | 优化最终求解的连接规模、重复映射和导出开销；不能靠减少分析范围改善计时 |

## 5. 对齐的实现顺序与验收

以下条目是实施计划，**尚未增加所列的新命令行开关或完整功能**。机器可读清单见 [experiments/bpax_alignment.csv](experiments/bpax_alignment.csv)。

### M0：建立共同输入与覆盖口径

涉及 `tools/generate_facts.py`、`tools/run_pipeline.py` 和实验归一化工具。

1. 记录函数来源、范围、实际 lift 范围、分析根、AT 候选、普通 CALL / tailcall / jump-table 类型。
2. 将独立调用点清单纳入结果汇总，保留没有目标和没有进入值传播的点。
3. 区分 `retained_for_analysis`、`reachable_from_main` 和 `reachability_unknown`。
4. 建立共享函数范围输入用于隔离前端差异；原生符号/CFG恢复方式另列实验。

验收：同一个 ELF 上固定分母一致；每个动态已观察调用点都有前端/传播/输出状态；超时不计空集；改变 AT 根策略必须写入元数据。

### M1：补普通调用、尾调用与寄存器传递的语义

涉及 `tools/vex2Datalog/parser.py`、`tools/generate_facts.py`、`rules/schema.dl`、`rules/analysis.dl`、`rules/ssa.dl`。

1. 增加调用类型与尾调用关系，区分普通间接跳转和 jump table，不能把所有未知 jump 都当尾调用。
2. 尾调用继承上层返回续点，不创建“尾跳转后下一条指令”的虚假返回。
3. CALL 压入返回地址，tailcall 复用原返回地址，栈参数坐标分别处理。
4. 对齐 caller-saved/callee-saved、返回寄存器、未定义返回值与新发现目标的传播。
5. 建立最小运算清单：拷贝、ITE、Add/Sub、必要 cast、完整/部分寄存器读写、指针宽度读写。

验收案例：普通间接调用后读取返回指针；调用者保存的函数指针跨调用存活；嵌套间接调用；递归；直接/间接尾调用；尾调用链最终返回给最初调用者；AMD64 32 位寄存器写入的零扩展语义。

SSA 的验收依据是传播结果和真实目标，不强制要求两者生成相同编号或同形状的 phi 关系。

### M2：对齐内存基础语义与对象划分

涉及 `tools/memory_model.py`、`tools/offset_model.py`、`tools/stack_arguments.py`、`rules/offset_memory.dl`、分块规则。

1. 增加多对象分块的实验策略，让“分块”和“偏移”成为独立配置；保留现有粗块作为受控消融组。
2. 对齐全局初始化、函数地址/PLT 地址、指针宽度和只读块保护。
3. 对齐普通调用/尾调用的栈参数转换，已认证位置精化，未知情况保留明确回退。
4. 分配器和内存复制摘要按 ABI 列出支持范围，补 X86 参数读取和其他确有测试需求的语义。
5. 独立启用/关闭栈参数映射和快照，以测量增益与开销。

验收：共同块/不同块两种实验可区分；未知偏移不会越过对象身份无条件污染所有块；只读全局表不被伪写污染；现有字段/内部指针/参数真值不退化；缺失摘要显式可见。

### M3：达到可运行的性能与覆盖基线

先把 M0–M2 的功能模块化推进，每完成一个模块都复跑相关最小案例，不在最后才统一验证。

1. 诊断 `stack_argument_value` 回退连接，先把重复的调用点/源位置候选去重再连接 store；不能删除未知分支来换时间。
2. 用 profile 检查 points_to_offset、跨函数映射和重复导出的规模；区分输入扫描、推导和结果写盘。
3. 接受更长预算确认功能后，在相同预算、线程、输入和统计口径下比较完成率。

验收：至少完成 BPA-X 在共同预算内已经完成的 4 个 xz 配置；逐调用点审计丢失的 BPA-X 预测边。对动态真边，目标是保留全部已观察边；只达到“与 BPA-X 一样漏 14 条”不足以支撑准确性提升。

只有在双方完成并具有可比覆盖时，才讨论候选数与速度差异。正式性能组独立重复；本轮 180 秒筛查和一次 profile 不替代稳定性能结论。

### M4：在共同覆盖基础上实现实质增强

优先补 SIMD/宽读写，这是双方已有最小复现的缺口：

```text
64UtoV128 / XMM 局部写入
  → 按 lane 或字节片段保留指针身份
  → 合并/提取/128位 load-store
  → 正确恢复两个字段的指针
```

先要求 SIMD 诊断中的 alpha 不丢失，并将它与 beta 放在正确字段。不能把整个 128 位值当单个函数地址，也不能简单把 64UtoV128 当普通无位置 copy。

随后验证已有块内偏移、参数快照在同覆盖基础上的收益，最后再考虑普通内存强更新、选择性上下文敏感和 demand-driven 分析。

## 6. 怎么组织基线与增强，避免混在一起

建议逐步提供以下独立维度，先落到内部配置和 summary，确认稳定后再暴露 CLI。名称仅为建议，尚未实现：

| 维度 | 建议选择 | 要回答的问题 |
| --- | --- | --- |
| function source / analysis roots | 共享函数清单 / 自动恢复；main / main+AT | 函数输入和分析范围是否相同 |
| partition | 当前粗块 / 代码推断的对象块 | 收益来自对象划分还是偏移 |
| memory model | block / heap-offset / offset | 块内位置精化的增益和代价 |
| stack arguments | 保守摘要 / SP映射 / SP映射＋快照 | 精确坐标与写入时序分别贡献多少 |

“功能对齐基线”使用一致的输入条件、根策略和基础调用语义；“增强组”在此基础上逐个打开偏移/快照等机制。不能把当前 block 模式重新命名为 bpa-x-compatible 就宣布已经对齐。

未知情况可以标记为部分解析并保留保守候选；保守候选全集如何选择也必须有明确假设与测试。`unknown_value` 当前是诊断关系，不会自动将所有可能函数加入调用目标。

## 7. 对齐和超过的判定标准

### 功能对齐

- 每个基础能力都有明确入口、语义和回归案例，调用点/目标差异可以解释。
- 已支持范围内的精确真值案例没有新增 FN。
- 同一输入上 BPA-X 能完成的配置，本项目在约定资源预算内也能完成。
- 新调用目标能够触发所需参数、返回、栈映射与后继调用推导；未覆盖部分显式呈现。
- 自动函数发现和 stripped 能力单列验证；有符号模式通过不等于完成 stripped 端到端分析。

### 超过 BPA-X

- 在具体能力上解决基线的已证实缺陷，例如 SIMD 写入丢指针，并有真实二进制和最小案例支持。
- 在相同输入和分析范围上保留全部已观察真边，再通过人工完整真值或差异复核证明排除了不可能目标。
- 同时报告候选数、覆盖、漏边、时间、内存、超时和未知情况；给出机制消融。

研究贡献可以是“更精确的位置抽象＋覆盖完整的指针传输语义＋可扩展求解”。目前位置抽象与参数精化已有基础；覆盖与性能仍是必须完成的工程与研究工作。
